# DSH Tablet Client 功能说明

> 把闲置的旧 Android 平板变成 Agent 监控台：插电立在桌上，永不熄屏、常驻前台、开机自启，随时瞥一眼 Agent 在干什么，审批 / 提问直接在平板上处理。
>
> 支持两种后端：**DSH**（DeepSeek Harness）与 **opencode**，可同时绑定多台 PC。

---

## 一、整体布局

App 为底部三 Tab 结构（`MainShell`，IndexedStack 保留各页状态）：

| Tab | 名称 | 职责 |
|-----|------|------|
| 1 | 控制台 | 全部绑定机器的健康状态 + 跨机器的会话聚合视图 |
| 2 | 对话 | 当前机器的实时对话、审批、文件变更 |
| 3 | 设置 | 设备管理 / 常驻 / 通知声音 / 外观 / 会话 / 应用更新 |

对话页是全局唯一状态源（`SessionState`）的驱动者，其余页面只读；切机器即重建对话页并重新 `boot()`。

---

## 二、控制台

- **顶部机器条**：每台绑定机器一张设备卡，各自显示连接健康度（该机器自己的轮询通道，8 秒一轮）。
- **跨机器混排的会话列表**，分三组：
  - 🟢 **进行中** —— Agent 正在运行的会话，实时显示；
  - 🟠 **待查看** —— 后台完成但你还没看的会话，带 NEW 标；
  - 📋 **最近活跃** —— 最近 3 小时内对话过的会话，快速切换。
- **手势语义唯一**：
  - 点**设备卡** = 只切当前机器（留在控制台）；
  - 点**会话行** = 切机器 + 跳对话页 + 打开该会话。
- **完成感知是边沿触发**：某会话从「运行中」变「空闲」才触发一次（未读标 + 提示音 + 系统通知），且跳过你正盯着看的会话。
- 子 Agent 会话（`origin == 'subagent'`）在数据入口统一过滤，不出现在任何列表里。
- 点系统通知可直达「对应机器 + 对应会话」，冷启动由通知拉起同样能路由。

---

## 三、对话

### 实时对话
- 流式输出 + Markdown 渲染，历史回填（最近 50 条）。
- **轮次状态机 V4**（对标 dsh-go）：`idle → sending → queued → running` 单一 `phase` 字段表达阶段，`generation` CAS 丢弃迟到/乱序的旧状态，UI 只见迁移前后、不见中间帧。
- **排队可视化**：本轮收尾但 Host 队列里还有你的消息时显示排队横幅，此期间停止按钮保持可用（不因 turn 间隙闪断）。
- **过程步骤卡 + 工具状态栏**：正在执行哪个工具一目了然。
- 停止生成：任一「忙」相位都可取消。
- 左侧**会话抽屉**：按工作区分组、支持新建会话与切换；右侧**变更栏**：文件变更 diff 实时查看（行级 diff 算法）。

### 模型与模式
- 会话内可切换**模型**（模型目录来自后端）；
- opencode 后端额外支持切换**模式**（build / plan 等 agent），DSH 无此概念则入口自动隐藏。

### 连接状态点
对话页顶部的状态点**只代表当前机器**，四态：

| 状态 | 颜色 | 条件 |
|------|------|------|
| connecting | 橙 | 建连中 / 数据未校验 |
| healthy | 绿 | WebSocket 已连 **且** 最近一次会话列表拉取成功（二者缺一不可） |
| degraded | 橙「数据异常」 | socket 通但列表拉取失败 |
| offline | 红「未连接」 | 连接已断 |

状态点可点开查看连接 / 建连中 / 数据校验三个原始字段与失败原因。断线自动重连（独立重连策略模块）。

---

## 四、审批与提问

DSH Web 端的审批 / 提问交互完整移植到平板：

- **审批卡**：Agent 请求权限（执行命令、改文件等）时，平板上直接 **允许 / 拒绝**；
- **提问表单**：Agent 向用户提问时弹出可交互表单，直接在平板上作答；
- 待办在控制台设备卡上有角标提示；轮次结束时已处理的卡片自动清理，不残留。

---

## 五、通知

- 本地 heads-up 通知，**分类开关**独立控制：审批 / 提问 / 表单 / 完成；
- 点通知直达对应机器的对应会话（机器已被删除的旧通知只打开 App、不跳转）；
- 通知出口实时读取设置里的分类开关（闭包持有，非启动快照）。

## 六、设置

iOS 风格二级菜单，根页只列「去哪」，具体项各自一个二级页：

### 设备管理
- 绑定多台 PC，每台可命名；支持 **DSH** 与 **opencode** 两种后端；
- **免连接连接测试**（纯 REST，不需要先 open）；
- 授权方式：
  - DSH：粘贴启动链接 / 扫码（启动令牌或 8899 配对页二维码）；
  - opencode：`opencode pair --remote` 授权链接换码，或服务密码直连；两者都支持扫码填入。

### 平板常驻
- **屏幕常亮**（默认开，WakelockPlus）；
- **前台保活**：常驻通知栏，防止进程被系统冻结（后台轮询依赖它）；
- **开机自启**（随保活服务）。

### 通知与声音
- 通知分类开关（见上）；
- 提示音：内置 3 种 + **自定义铃声**（mp3/wav/ogg，拷贝进应用私有目录，删源文件不受影响）。

### 外观
- 主题：跟随系统 / 浅色 / 深色（低饱和度 iOS 风格设计系统）。

### 会话
- 会话相关偏好（历史条数、归档会话的可见性等）。

### 应用更新
- 启动自动检查（可关）+ 手动检查，探测所有已绑定机器的 8099 下载服务；
- 更新下载是**事务式**的：先下到 `*.part` 临时文件并流式校验 SHA-256（声明了就 fail-closed，不匹配拒绝安装），通过后原子替换，旧包保留为 LKG 备份（同版本免下载重装）。

## 七、兼容性

| 项 | 要求 |
|----|------|
| Android | 8.0+（API 26+），ARMv7 / ARM64 / x86_64，内存 ≥ 1GB |
| 网络 | 平板与 PC 同一局域网 |
| DSH | 0.1.x，绑定 `0.0.0.0`（无需装任何插件，只用原生 HTTP API + WebSocket mux） |
| opencode | serve 模式（v2 API），授权链接或服务密码 |

已验证设备：RK3288 平板（Android 9，PHH Treble GSI，armeabi-v7a）。

## 八、架构速览（给开发者）

```
lib/
├── screens/        三 Tab + 设置二级页 + 扫码授权页（一页一 StatefulWidget）
├── widgets/        消息气泡 / 审批卡 / 问题表单 / 过程步骤卡 / 排队横幅 / 变更抽屉 …
├── services/
│   ├── agent_backend.dart    统一后端接口：dsh_backend / opencode_backend 同级实现
│   ├── server_manager.dart   聚合多台机器的轮询（每台一个 SessionMonitor，8s）
│   ├── session_state.dart    单一权威状态源（ChatController 驱动，其余只读）
│   ├── turn_supervisor.dart  轮次状态机唯一写入口（generation CAS）
│   ├── event_dispatcher.dart 全部事件对账/状态迁移的唯一通道
│   ├── dsh/                  DSH HTTP RPC + WebSocket mux 协议栈
│   └── opencode/             opencode v2 API 封装
├── models/         纯数据模型（TurnState / QueuedMessage / ProcessStep …）
└── theme/          ios_theme.dart 低饱和度设计系统
```

关键设计原则（详见 [STATE_AND_INTERACTION.md](STATE_AND_INTERACTION.md)）：

- **两层状态语义不重叠**：顶部状态点只代表当前机器，每台机器健康度由各自设备卡表达；
- **监控是全局的**：绑定几台就监控几台、就通知几台（后台机器的完成感知最多晚一个轮询周期 8s）；
- **事件只走一条路**：所有事件流经 EventDispatcher，对账与状态迁移只有一份；
- **接第三个后端 = 一个实现类 + 一个枚举值**，页面零改动。

### 协议接口（DSH）

| 接口 | 用途 |
|------|------|
| `POST /api/host.describe` | 连接检测 |
| `POST /api/session.*` | 会话列表 / 创建 / 发消息 / 历史 / 取消 |
| `POST /api/respond` | 审批 / 问题回答 |
| `WS /api/events.mux` | 实时事件流（流式输出 / 审批 / 变更 / 轮次） |
